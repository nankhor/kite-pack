# Convert Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Convert page that turns a dump into a fake package (.fpkg) with Forge's package writer, compression off by default, then optionally installs it on the PS5 (streamed) and deletes the .fpkg once the PS5 confirms it.

**Architecture:** Convert is a pack job in a new format, `OutputFormat::Pkg`. The pipeline plans `[Pack, InstallPackage?, DeletePacked?]` for it; the install step streams the packed copy instead of the source. The screen routes a job whose `format` is `pkg` to the Convert page, which reuses the Pack page's layout with its own options panel.

**Tech Stack:** Rust (kite-pipeline, kite-forge over vendored forge-core, kite-session, kite-ps5, Tauri 2 shell), React 19 + TypeScript + Vitest.

**Spec:** `docs/superpowers/specs/2026-11-25-new-look-design.md` (the **Convert** section).

## Global Constraints

- Compression off by default; Off maps to Forge's `KrakenLevel::Stored`, On to `KrakenLevel::Fast`. Hint: "Off installs on every firmware".
- No zstd packing for a package (`zstd_pack` is not allowed for `Format::Pkg`).
- Saved to the Packages folder from Settings; none set means next to the game.
- Install on PS5 streams the finished .fpkg; "Delete the .fpkg after" only once the PS5 confirms the install.
- Note on the page: "Needs kstuff with fake-package support running on the PS5."
- Copy as in the approved mockup: sidebar "Convert" / "Turn a dump into a .fpkg"; cards "Fake package" and "Then"; button "Convert and install" or "Convert".
- Light and dark themes, the tokens from PR #40; no new colours.

## Review Focus

1. An install-only job (a dropped .pkg, `install: true`, format Folder) must still plan `[InstallPackage]` and install the source, not a packed copy.
2. "Delete the .fpkg after" without Install on PS5 is refused, and DeletePacked never runs before InstallPackage is done.
3. A convert job resumed after a restart installs `job.packed`, not the dump.
4. A convert job finishing lands on the Convert page and in History as "Converted", not on Pack.
5. Old settings and history files (no `packagesFolder`, no `kind`) still load.
